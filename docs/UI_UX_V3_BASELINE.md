# LIGClaw UI/UX v3 기준선 감사

> 기준일: 2026-07-26  
> 대상: Precision Workspace v3 전환 직전 WPF 화면

## 대표 화면 기준

| 크기 | 용도 | 필수 확인 |
|---|---|---|
| 760×500 | 최소 compact | 주 탐색, 요청 입력, 전송/중단, 관리 페이지 핵심 필드 |
| 1060×650 | 현재 기본 창 | 일반 대화, 상태, 관리 화면의 정보 밀도 |
| 1440×900 | 넓은 작업 공간 | 최대 읽기 폭, 불필요한 카드 확장, 여백 균형 |

## 구조적 부채

1. compact 사이드바가 132px라 아이콘 rail도, 충분한 텍스트 내비게이션도 아닌 중간 상태다.
2. 최근 대화가 내비게이션 높이를 계속 점유해 주 목적지와 로컬 상태가 밀린다.
3. 정상 상태가 header pill과 하단 status bar에 중복된다.
4. 대화 제목, transcript 카드, composer 카드가 모두 독립적으로 강조돼 시선의 시작점이 분산된다.
5. Tool 진행은 단일 banner라 요청 → 승인 → 실행 → 결과 흐름을 충분히 표현하지 못한다.
6. 넓은 창에서 대화 읽기 폭 상한이 없어 문장과 표가 과도하게 늘어난다.
7. 관리 화면은 기능 패턴은 통일됐지만 셸의 command header와 시각적으로 연결되지 않는다.

## 스타일 부채 기준값

자동 집계 기준으로 `BrandTokens.xaml`을 제외한 11개 XAML에 다음 직접 값이 존재한다.

| 항목 | 기준값 | v3 목표 |
|---|---:|---:|
| 직접 FontSize | 29 | 신규 추가 0, 공용 스타일 전환으로 지속 감소 |
| 직접 Margin | 147 | 화면 고유 배치 외 spacing token 또는 공용 컴포넌트로 감소 |
| 직접 Padding | 7 | 공용 스타일로 전환 |
| 직접 CornerRadius | 4 | radius token으로 전환 |
| 문자 glyph 기능 아이콘 | 1 | 0 |
| view XAML 직접 HEX | 0 | 0 유지 |

간격은 화면의 위치 관계 자체이므로 모든 `Margin`을 기계적으로 토큰화하지 않는다. 반복되는 page/card/command 간격과 컴포넌트 내부 간격을 우선 토큰으로 옮기고, 고유 레이아웃 값은 의도를 설명할 수 있을 때만 남긴다.

## 보존해야 할 현재 강점

- 통합 MainWindow 안에서 설정·활동·기억·예약을 전환한다.
- 760×500 UI Automation smoke가 핵심 기능을 검증한다.
- semantic color token과 raw HEX 금지 검사가 이미 존재한다.
- 같은 대화의 세션 연속성, 명시적 새 대화, 최근 대화 복원이 동작한다.
- transcript 스크롤 위치 보존과 안전한 Markdown 렌더러가 있다.
- 진단은 별도 크기 조절 창으로 분리돼 정상 작업을 방해하지 않는다.

## V3-0 종료 판정

이 문서의 기준 크기, 구조적 부채, 정량 기준값을 v3 전/후 비교 기준으로 사용한다. 구현 중 기존 강점 항목이 하나라도 퇴행하면 시각 개선 완료로 판정하지 않는다.

## v3 완료 비교

| 항목 | 기준값 | 완료값 |
|---|---:|---:|
| 직접 FontSize | 29 | 0 |
| 문자 glyph 기능 아이콘 | 1 | 0 |
| view XAML 직접 HEX | 0 | 0 |

중복 상태 카드는 정상 흐름에서 제거했고, 최근 대화는 command header의 switcher로 이동했다. 대화 읽기 폭은 880px로 제한되며 compact shell은 72px, 일반 shell은 216px AppRail을 사용한다. 760×500과 1060×650 실제 렌더링 및 UI Automation smoke에서 기존 강점의 퇴행이 없음을 확인했다.
