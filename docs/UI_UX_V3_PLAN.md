# LIGClaw UI/UX v3 개선 계획

> 상태: V3-0~V3-7 구현 및 검증 완료  
> 기준일: 2026-07-26  
> 범위: WPF 통합 셸, 대화, 활동, 기억, 예약, 설정, 승인 및 진단 화면

## 1. 목표

LIGClaw를 단순한 채팅 창에서 **정밀하고 신뢰할 수 있는 Windows 작업 지휘 공간**으로 발전시킨다. 첫 화면은 멋있어야 하지만 장식이 기능을 덮지 않아야 하며, 사용자는 현재 상태·다음 행동·실행 결과를 한눈에 이해할 수 있어야 한다.

제품 인상은 다음 네 단어로 고정한다.

- **정밀함**: 선명한 정렬, 구조화된 실행 상태, 예측 가능한 반응
- **신뢰감**: 깊은 청색, 충분한 대비, 명확한 승인과 결과
- **진취성**: 사선과 전진 방향의 제한된 그래픽 모티프
- **절제**: 불필요한 카드·배지·장식을 줄이고 작업에 화면을 양보

## 2. 공식 사이트에서 가져올 원칙

참고 기준은 [LIG Defense&Aerospace 공식 홈페이지](https://www.ligdefenseaerospace.com/main.do)와 [공식 CI 안내](https://www.ligdefenseaerospace.com/news/ci.do)다.

공식 CI는 두꺼운 획을 전문성·안정성·신뢰감으로, `L`과 `G`의 사선 포인트를 혁신과 미래 성장으로 설명한다. 메탈릭한 다크 블루와 그레이는 첨단 기술과 미래 이미지를 표현한다. 공식 홈페이지는 큰 제목, 넉넉한 여백, 한국어와 영문 분류명의 조합, 장면 단위의 강한 시각 전환으로 사업 영역을 전달한다.

LIGClaw에는 다음처럼 번역한다.

| 공식 표현 | LIGClaw 적용 |
|---|---|
| 다크 블루와 메탈릭 그레이 | 셸, 선택 상태, 중요 명령, 경계선의 핵심 팔레트 |
| 두꺼운 획과 명확한 워드마크 | 짧고 굵은 페이지 제목과 높은 정보 위계 |
| 전진하는 사선 | 선택 표시, 진행 단계, 빈 화면 배경의 제한적 모티프 |
| 큰 장면과 여백 | 한 화면에 하나의 주 작업, 넓은 대화 본문, 낮은 시각 소음 |
| 한글+영문 영역명 | `대화 / ASSIST`, `활동 / ACTIVITY`처럼 주요 위치에만 제한 사용 |
| 스크롤 기반 서사 | 요청 → 판단 → 승인 → 실행 → 결과의 시간 흐름으로 변환 |

공식 로고나 워드마크를 변형하지 않는다. LIGClaw의 기존 독자 심벌을 유지하고 공식 기업 사이트의 사진·영상·그래픽을 앱 자산으로 복제하지 않는다.

## 3. 비주얼 콘셉트: Precision Workspace

### 3.1 색상

- `Brand / Innovative Blue #002F6D`: 셸과 주요 선택 상태
- `Brand / Futuristic Gray #D0D3D4`: 보조 면과 금속성 경계
- `Deep Navy`: 창 상단과 내비게이션의 깊이 표현
- `Ice Blue`: 선택·정보·도우미 응답의 낮은 채도 배경
- `Signal Cyan`: 진행 중인 작업에만 제한적으로 사용
- `Success / Warning / Danger`: 의미 상태 전용이며 브랜드 청색과 혼용하지 않음

색상값은 화면에 직접 쓰지 않고 의미 토큰으로만 사용한다. 밝은 기본 테마를 우선하되, 후속으로 동일 의미 토큰을 사용하는 다크 테마를 추가할 수 있게 설계한다.

### 3.2 타이포그래피

- 페이지 제목은 현재보다 크고 굵게 하되 한 줄로 제한한다.
- 본문은 `Segoe UI Variable`을 유지하고 읽기 폭과 행간을 개선한다.
- 숫자·시간·용량·실행 ID는 tabular number 또는 mono 스타일을 사용한다.
- 영문 보조 라벨은 작은 대문자와 넓은 자간으로 사용하되 모든 텍스트를 영문화하지 않는다.
- 긴 설명보다 `상태 + 핵심 결과 + 다음 행동` 순으로 문장을 줄인다.

### 3.3 형태와 깊이

- 중첩된 흰색 카드 사용을 최소화한다.
- 페이지 배경, 작업 면, 떠 있는 composer의 3단계 깊이만 기본으로 사용한다.
- 테두리는 얇고 차갑게, 그림자는 넓고 매우 약하게 사용한다.
- radius는 작은 컨트롤 6, 패널 10, composer 14 수준으로 통제한다.
- 사선은 장식용 반복 패턴이 아니라 선택 표시와 진행 방향에만 사용한다.

### 3.4 아이콘과 모션

- 동일한 20px optical size와 한 가지 선 굵기의 아이콘 세트를 사용한다.
- 문자 기호 `＋`, `●`, `⌃`를 기능 아이콘으로 남용하지 않는다.
- 전환은 120~180ms의 opacity/translate 정도로 제한한다.
- 스트리밍 중에는 컨테이너가 흔들리지 않도록 높이 변화와 자동 스크롤을 묶어서 처리한다.
- Windows 동작 줄이기 설정에서는 비필수 모션을 제거한다.

## 4. 정보 구조 개편

### 4.1 앱 셸

현재 고정 폭 사이드바를 다음 구조로 바꾼다.

```text
┌──────────────────────────────────────────────────────────────┐
│ LIGClaw   현재 대화                    연결 상태   명령 검색 │
├────────┬─────────────────────────────────────────────────────┤
│ ASSIST │                                                     │
│ ACTIVITY        선택된 페이지의 전체 작업 공간              │
│ MEMORY │                                                     │
│ SCHEDULE                                                    │
│ SETTINGS│                                                    │
├────────┤                                                     │
│ profile│                                                     │
└────────┴─────────────────────────────────────────────────────┘
```

- 기본 내비게이션은 72px rail이며 넓은 창에서만 216px로 확장한다.
- `새 대화`는 항상 찾을 수 있는 상단 primary command로 이동한다.
- 최근 대화 전체 목록을 내비게이션에 계속 노출하지 않고, 대화 검색/전환 drawer로 분리한다.
- 연결 상태는 한 위치에서만 보여주며 정상 상태는 조용하게, 문제 상태는 복구 행동과 함께 강조한다.
- 진단 로그와 기술 상태는 일반 홈에서 제거하고 문제 해결 창과 설정에 둔다.

### 4.2 대화 홈

- 빈 대화에서는 중앙의 큰 composer와 4개 이하의 실제 가능한 예시 명령을 보여준다.
- 대화가 시작되면 composer는 하단에 붙고 본문은 최대 읽기 폭 880px 안에서 중앙 정렬한다.
- 사용자 요청은 간결한 명령 블록, 도우미 답변은 문서형 본문으로 구분한다.
- 실행 Tool은 별도 JSON이나 일반 답변이 아니라 단계형 `Action Card`로 표시한다.
- 관련 도구 결과가 끝나면 긴 기술 결과를 접고 핵심 요약과 `자세히`만 남긴다.
- 사용자가 위 내용을 읽는 동안 새 응답이 와도 위치를 강제로 이동하지 않고 `새 응답 ↓` 버튼을 표시한다.

### 4.3 실행 흐름

모든 실행은 아래 공용 상태 모델을 시각화한다.

```text
요청됨 → 분석 중 → 승인 필요 → 실행 중 → 완료
                   └→ 거부됨      └→ 실패/부분 완료
```

- 상태마다 아이콘, 텍스트, 시간, 가능한 행동을 함께 표시한다.
- `분석 중` 같은 불확정 상태는 무한 spinner 대신 현재 수행 중인 범주를 보여준다.
- 취소는 영향을 설명하고, 이미 완료된 부분이 있으면 완료 범위를 보존한다.
- 성공 toast만 띄우고 사라지게 하지 않고 타임라인과 활동 이력에 결과를 남긴다.

### 4.4 관리 페이지

- 활동: 날짜 중심 타임라인, 상태·위험 필터, 실패/부분 완료 우선 탐색
- 기억: 종류별 그룹보다 검색 중심, 값·출처·만료·마지막 사용을 한 행에 표현
- 예약: `오늘 / 예정 / 확인 필요 / 지난 항목`으로 시간 중심 재구성
- 설정: 긴 단일 폼 대신 `모델 연결 / 동작 및 시작 / 권한 / 데이터 / 문제 해결` 섹션
- 모든 관리 페이지는 동일한 page header, command bar, filter chip, data row, empty state를 사용한다.

### 4.5 승인 창

- 상단에 위험 수준보다 사용자가 하려는 일을 먼저 적는다.
- 대상, 범위, 외부 전송 여부, 되돌리기 가능 여부를 고정 순서로 표시한다.
- `이번만 허용`을 기본 동작으로 하고 `항상 허용`은 범위와 만료를 펼쳐 확인한 뒤 선택한다.
- 승인 버튼에 위험 색상을 무분별하게 쓰지 않는다. 위험은 설명과 범위로 전달하고 파괴적 행동만 Danger를 사용한다.

다음 컴포넌트를 먼저 만들고 화면은 이를 조합한다.

컴포넌트는 normal, hover, pressed, selected, focus-visible, disabled, busy, error 상태를 모두 갖는다. 화면별 복제 스타일은 만들지 않는다.

## 6. 구현 단계

### V3-0 — 기준선과 시각 감사

- 현재 주요 화면을 760×500, 1060×650, 1440×900으로 캡처
- 중복 카드, 직접 색상, 직접 글꼴 크기, 문자 아이콘, 고정 폭을 목록화
- 대화·도구·승인·관리 페이지의 정보 우선순위 확정

완료 조건: 전/후 비교 기준과 제거할 시각 부채 목록이 문서화된다.

### V3-1 — 토큰과 컴포넌트 기반

- 색상, 타이포그래피, spacing, radius, border, elevation, motion 토큰 v3 구축
- AppRail, command header, button, input, tag, banner, focus visual 구현
- XAML의 직접 색상·크기 사용을 회귀 검사로 제한

완료 조건: 셸과 신규 컴포넌트가 화면별 magic number 없이 토큰으로 렌더링된다.

### V3-2 — 새 셸과 대화 전환

- 72/216px adaptive AppRail 구현
- 최근 대화를 검색 가능한 switcher/drawer로 이동
- 상단 command header와 단일 연결 상태 구현
- compact layout에서 rail·header·본문이 겹치지 않도록 보강

완료 조건: 모든 페이지가 새 셸에서 동일한 탐색과 제목 구조를 사용한다.

### V3-3 — 대화 경험 재설계

- hero/docked composer 전환
- 최대 읽기 폭과 문서형 응답 스타일 적용
- Action Card 및 새 응답 indicator 구현
- Markdown 표·코드·목록·링크·복사의 시각 규칙 통일

완료 조건: 긴 대화, 스트리밍, 도구 실행, 사용자 수동 스크롤에서 위치와 레이아웃이 안정적이다.

### V3-4 — 관리 화면 재구성

- 활동, 기억, 예약을 새 command bar와 data row 패턴으로 전환
- 설정을 다섯 섹션으로 재구성하고 저장 상태를 명확히 표시
- 빈 상태, 검색 결과 없음, 로딩, 실패, 부분 성공 표현 통일

완료 조건: 관리 화면마다 동일 행동이 같은 위치·모양·키보드 흐름을 가진다.

### V3-5 — 승인과 복구 경험

- 승인 정보 계층과 항상 허용 범위 UI 개선
- 실패 원인, 재시도, 설정 이동, 진단 열기를 문맥형 recovery action으로 통일
- 취소·부분 완료·되돌리기 결과의 상태 연결 보강

완료 조건: 모든 실행 상태에 사용자가 선택할 수 있는 명확한 다음 행동이 있다.

### V3-6 — 시각 완성도와 접근성

- 독자 심벌과 사선 모티프를 empty state·선택 상태에 절제해 적용
- 고대비, 키보드, screen reader, 긴 한국어·영문, 760×500 검사
- 모션 감소와 포커스 복원 검증

완료 조건: 시각 개선이 대비·키보드·작은 화면 요구사항을 퇴행시키지 않는다.

### V3-7 — 실기 검증과 정리

- UI Automation smoke에 새 셸, 대화 전환, Action Card, 관리 페이지 추가
- 대표 크기 캡처와 전/후 휴리스틱 리뷰
- 사용하지 않는 v2 스타일과 레이아웃 분기 제거
- 전체 `./scripts/verify.ps1`과 UI/Sidecar smoke 수행

완료 조건: 기능 회귀 0, 애플리케이션 오류 0, 직접 스타일 부채 목표치 충족, 문서와 실제 화면 일치.

## 8. 정량 acceptance

- 760×500에서 대화 입력, 전송/중단, 주 탐색이 항상 viewport 안에 존재
- 일반 폭에서 대화 본문 최대 읽기 폭 880px 이하
- 한 화면의 주요 action은 원칙적으로 1개, 보조 action은 3개 이하
- 정상 상태의 상시 status UI는 한 위치만 사용
- 화면 XAML에 새 직접 HEX 색상 추가 0건
- icon-only 버튼의 접근성 이름 누락 0건
- 새 terminal state 없는 비동기 UI 경로 0건
- 스트리밍 중 사용자가 하단에서 벗어난 경우 강제 자동 스크롤 0건
- 대표 UI smoke 중 Application 오류 0건
- 전체 자동 테스트, 포맷, 계약 drift 검사 통과

## 9. 제외 범위

- WinUI 3 마이그레이션
- 공식 기업 사이트의 사진·영상 자산 복제
- 공식 LIG 워드마크 변형 또는 제품 심벌과 결합
- 기능이 없는 장식성 3D, 레이더, 지도, 군용 HUD
- UI 개편을 이유로 Tool 승인·저장소·프로세스 소유권 변경
- 음성, OCR/VLM, 브라우저 자동화 같은 신규 제품 기능

## 10. 완료 기록

V3-0부터 V3-7까지 구현했다. 기준선 감사, 의미 토큰과 공용 컴포넌트, 72/216px adaptive AppRail, conversation switcher, hero/docked composer, 880px 읽기 폭, Action Card, 새 응답 indicator, 관리 페이지 command bar/data surface, 승인·복구 정보 계층을 실제 WPF 화면에 반영했다.

최종 자동 검증은 Sidecar 59개, Contracts 7개, Application 18개, Desktop 187개, Named Pipe 통합 1개 테스트가 통과했다. UI smoke는 760×500 compact layout, 통합 페이지 4개, 대화 경계, 키보드 탐색, Precision Workspace 동작과 Application 오류 0건을 확인했으며 Sidecar smoke도 통과했다. 화면 XAML의 직접 숫자 `FontSize`, 문자 glyph 기능 아이콘, 직접 HEX 색상은 각각 0건이다.
