# LIGClaw 디자인 시스템

> 상태: Phase 1 진입 전 기준 v1  
> 기준일: 2026-07-25

## 1. 브랜드 기준과 사용 원칙

LIGClaw의 시각 언어는 [LIG Defense & Aerospace CI](https://www.ligdefenseaerospace.com/news/ci.do)가 설명하는 전문성, 안정감, 신뢰감과 대각선의 전진성을 제품 UI에 맞게 해석한다.

공식 원색은 다음 값을 그대로 보존한다.

| 토큰 | 공식 명칭 | Pantone | RGB | HEX | 제품 용도 |
|---|---|---|---|---|---|
| `BrandBlue` | LIG Innovative Blue | 294 C | 0, 47, 109 | `#002F6D` | 내비게이션, 주요 동작, 브랜드 면 |
| `BrandGray` | LIG Futuristic Gray | 427 C | 208, 211, 212 | `#D0D3D4` | 아이콘 보조 면, 구분, 미래지향적 중립색 |

공식 LIG 워드마크와 `LIG Defense&Aerospace` 시그니처는 기업 식별 자산이다. 제품 아이콘으로 재조합하거나 글자 형태를 수정하지 않는다. LIGClaw는 혼동을 피하기 위해 별도의 제품명과 독자 심벌을 사용한다. 공식 CI 원본이 필요한 대외 제작물에서는 CI 페이지가 제공하는 원본 파일과 사용 규정을 우선한다.

## 2. 제품 심벌

LIGClaw 심벌은 열린 C형 몸체와 오른쪽으로 진행하는 세 개의 대각선으로 구성한다.

- C형 몸체: 사용자의 요청을 감싸는 개인 비서와 `Claw`의 첫 글자
- 세 개의 대각선: 관찰, 판단, 실행의 진행 단계
- 진한 청색 바탕: 신뢰 가능한 로컬 실행 경계
- 흰색과 Futuristic Gray: 작은 트레이 크기에서도 분리되는 고대비

심벌은 공식 LIG 워드마크를 베끼거나 변형한 것이 아니며 제품 식별용이다. 최소 16px에서도 세 대각선이 구분되도록 세부 요소를 추가하지 않는다. 앱 아이콘과 트레이 아이콘은 동일한 실루엣을 사용한다.

자산은 `scripts/generate-brand-assets.ps1`의 좌표와 공식 색상 토큰에서 결정적으로 생성한다. AI 에이전트가 원본 벡터 의도를 추적하고 크기별 ICO를 재현할 수 있도록 바이너리만 수작업 편집하지 않는다.

## 3. UI 방향

화면은 “정밀한 운영 콘솔이지만 개인 비서답게 편안한 도구”를 목표로 한다.

- 브랜드 청색은 왼쪽 내비게이션과 주요 버튼에 집중하고 넓은 본문은 밝은 중립색으로 유지한다.
- 사용자가 가장 먼저 보는 요청 입력과 실행 버튼을 하나의 작업 카드로 묶는다.
- 응답 스트림과 런타임 진단을 분리해 정상 사용 시 기술 정보가 주 작업을 압도하지 않게 한다.
- 일반 화면에는 런타임 이름, 패키지 버전, fixture, protocol 같은 구현 용어를 노출하지 않는다. 진단 정보는 사용자가 직접 펼치는 문제 해결 영역에만 둔다.
- 아직 사용할 수 없는 메뉴는 탐색 항목처럼 보이게 미리 배치하지 않는다.
- 위험 동작은 청색이 아닌 `Danger` 색을 사용하고, 상태는 색상뿐 아니라 문구로 함께 전달한다.
- 본문 문장은 한국어를 기본으로 하고 프로토콜명, 런타임명처럼 검증에 필요한 고유명만 영어를 유지한다.

## 4. 디자인 토큰

구현의 단일 진실 공급원은 `Themes/BrandTokens.xaml`이다. View에서 색상 값을 직접 추가하기보다 의미 토큰을 사용한다.

| 범주 | 토큰 | 값/의도 |
|---|---|---|
| Brand | `BrandBlue`, `BrandGray` | 공식 CI 원색 |
| Surface | `Canvas`, `Surface`, `SurfaceMuted`, `BrandIce` | 배경과 카드 계층 |
| Text | `TextPrimary`, `TextSecondary`, `TextOnBrand` | 정보 위계와 대비 |
| State | `Success`, `Warning`, `Danger`, `Inactive` | 런타임 및 승인 상태 |
| Radius | `Small 6`, `Medium 10`, `Large 16` | 컨트롤, 패널, 카드 |
| Type | `Segoe UI Variable Text`, `Cascadia Mono` | UI와 진단 로그 |

간격은 4px 배수를 기본으로 하며 카드 내부 22px, 카드 사이 18~24px, 페이지 바깥 28~34px을 권장한다. 애니메이션은 상태 이해에 필요한 경우에만 120~200ms 범위로 사용하고 운영체제의 동작 줄이기 설정을 존중한다.

## 5. 접근성과 Windows 동작

- 본문과 배경은 WCAG AA 수준의 대비를 목표로 한다.
- 포커스, 오류, 실행 중 상태는 색상만으로 표현하지 않는다.
- Windows 배율 100~200%와 최소 창 크기에서 주요 실행/취소 버튼이 잘리지 않아야 한다.
- 창 닫기는 트레이로 숨기며, 실제 종료는 트레이 메뉴의 `종료`에서 명시적으로 수행한다.
- 트레이 도구 설명은 제품명과 역할을 함께 표시하고, 더블 클릭하면 기존 창을 복원한다.

## 6. 유지보수 규칙

1. 공식 CI 원색 변경은 이 문서와 `BrandTokens.xaml`, 자산 생성 스크립트를 함께 수정한다.
2. 새 화면은 기존 의미 토큰과 공용 스타일을 먼저 재사용한다.
3. 공식 로고 파일을 제품 심벌 위치에 추가하지 않는다.
4. 아이콘 변경은 생성 스크립트, 256px 미리보기, 앱/트레이 ICO를 한 커밋에서 갱신한다.
5. 화면 변경 후 빌드와 자동화 테스트에 더해 실제 렌더링을 100%, 150% 배율에서 확인한다.
