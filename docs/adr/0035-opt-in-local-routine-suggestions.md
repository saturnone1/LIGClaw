# ADR 0035: opt-in local routine suggestions

- 상태: 승인
- 날짜: 2026-08-02

## 결정

반복 작업 제안은 기본 비활성이며 사용자가 설정에서 명시적으로 켠 경우에만 동작한다. Desktop은 이미 로컬 SQLite에 저장된 최근 45일의 완료된 사용자 요청을 최대 200개만 읽고, 공백과 대소문자만 정규화한 동일 요청이 서로 다른 날짜에 3회 이상 나타날 때 후보를 계산한다. 최근 3개 날짜의 간격이 모두 1~3일이면 매일, 모두 5~9일이면 매주 후보로 한정하며 의미 모델이나 외부 API는 사용하지 않는다.

화면 OCR·Explorer 선택 문맥, 자격 증명으로 보이는 문구, 이미 예약·알림 의도가 명시된 요청은 후보에서 제외한다. 제안 이력과 사용자의 `다시 제안하지 않기` 선택에는 요청 원문 대신 SHA-256 fingerprint와 UTC 시각만 HKCU 설정에 최대 100개 저장한다. 최근 제안 후 14일 동안 같은 요청을 다시 제안하지 않으며 설정에서 기록을 초기화할 수 있다.

제안 카드는 자동 실행이나 자동 예약을 하지 않는다. 사용자가 `예약 설정`을 선택하면 기존 Agent 작업 편집기에 요청, 추정 반복 주기, 다음 실행 시각만 미리 채운다. 사용자는 시간대·실행 제한·재시도·놓친 실행 정책을 검토하고 `예약`을 눌러야 저장할 수 있고, 실제 Windows 효과는 실행 시점의 기존 Desktop 승인 정책을 그대로 거친다.

## 이유

- 원문을 새 저장소나 진단 로그에 복제하지 않고 기존 로컬 대화 데이터만 bounded 조회한다.
- 정확 일치와 분명한 날짜 간격만 사용해 일반 사용자가 이해하기 어려운 추론과 오탐을 줄인다.
- 기능 전체 끄기, 이번 제안 닫기, 항목별 영구 무시, 무시 목록 초기화를 모두 제공한다.
- 기존 Agent 작업 계약과 승인 경계를 재사용해 별도 백그라운드 실행 통로를 만들지 않는다.

## 결과

- 표현이 달라진 의미상 동일 작업은 제안하지 않는다. 향후 확대하려면 별도 opt-in, 데이터 전송 표시, 평가 자료가 필요하다.
- 월간·불규칙 패턴은 현재 제안하지 않는다.
- HKCU 설정 형식과 최근 완료 요청 조회는 Desktop 소유이며 Domain/Application이나 Sidecar에 Windows·SQLite 의존성을 추가하지 않는다.
