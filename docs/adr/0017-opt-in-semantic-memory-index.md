# ADR 0017 — 선택형 의미 기억 색인

## 결정

Desktop은 사용자가 설정에서 명시적으로 켠 경우에만 OpenAI 호환 embedding endpoint를 사용한다. endpoint는 HTTP(S) 형식과 요청·응답 크기만 검증하며, localhost·사내망·공인망 주소를 구분해 차단하지 않는다. 설정 화면에는 검색어와 만료되지 않은 기억 내용이 구성한 endpoint로 전송된다는 범위를 표시한다. API 키는 Windows 자격 증명 관리자에 저장한다.

SQLite schema 9의 `memory_embeddings`에는 기억 원문을 복제하지 않고 기억 ID, endpoint·모델에서 만든 SHA-256 모델 식별자, 내용 해시, 차원, float32 벡터와 갱신 시각만 저장한다. 기억 수정은 내용 해시 비교로 지연 재색인하고, 기억 삭제는 외래키 연쇄 삭제로 벡터를 함께 제거한다. 만료 기억은 검색과 재색인 후보에서 제외한다.

검색은 기존 literal keyword 결과와 cosine vector 결과를 reciprocal-rank 방식으로 결합한다. endpoint 장애, 잘못된 응답 또는 차원 불일치가 발생하면 기억 Tool은 keyword 검색으로 복구한다. 취소는 HTTP 요청과 색인 저장까지 전파하며, 동시 색인은 한 프로세스 안에서 직렬화한다.

## 이유

- 에어갭 환경에서는 사용자가 운영하는 로컬·사내 embedding 서버를 우선 사용할 수 있어야 한다.
- 네트워크 위치를 앱이 추측해 차단하지 않으면서 실제 전송 범위를 사용자에게 명확히 보여 준다.
- 기억 원문 중복 저장과 오래된 벡터 잔존을 피한다.
- embedding 서버가 없어도 기존 기억 조회 기능을 잃지 않는다.

## 결과

- 의미 기억은 기본 비활성이며 설정 전에는 네트워크 요청이나 벡터 색인이 발생하지 않는다.
- 처음 검색하거나 기억 내용이 바뀐 뒤 검색할 때 필요한 항목만 최대 500개, 32개 단위로 재색인한다.
- 모델 또는 endpoint가 바뀌면 별도 모델 식별자로 다시 색인하며 기존 벡터는 검색에 사용하지 않는다.
- 임베딩 호출 로그에는 API 키, 검색어, 기억 원문을 기록하지 않는다.
