# ADR 0016 — 만료되는 exact-scope 지속 승인

## 결정

Desktop은 사용자가 승인창에서 직접 선택한 `30일 동안 항상 허용` 결정을 SQLite `capability_grants`에 저장한다. 지속 승인은 R1 중 adapter가 안정적인 `GrantScope`를 명시한 동작에만 제공한다. 최초 범위는 등록 앱 실행, 동일한 개인 기억 저장, 동일한 알림 예약이다. R2·R3·R4와 클립보드·파일 내용·UI Automation·외부 MCP에는 제공하지 않는다.

저장 범위는 canonical Tool 이름, Desktop이 재검증한 위험도와 adapter가 만든 정확한 대상/내용 scope를 SHA-256으로 해시한 값이다. 원본 인자, 기억 값, 알림 내용, 파일·클립보드 내용과 모델의 요청 이유는 grant 테이블에 저장하지 않는다. 승인 미리보기는 매 호출 다시 만들고 대상 identity를 고정한 뒤 활성 grant 지문과 비교한다. 일치할 때만 승인창을 생략하며 실행은 기존 Desktop 정책·감사 파이프라인을 그대로 통과한다.

grant는 생성 후 30일에 만료되며 설정의 `항상 허용한 동작` 목록에서 개별 철회할 수 있다. 최초 실행이 성공한 뒤에만 저장하고, 저장 실패 시 해당 실행은 일회 승인으로만 남는다.

## 이유

- 모델이나 Sidecar가 권한 범위·위험도·만료를 정하지 못하게 한다.
- Tool 전체를 영구 허용하지 않고 사용자가 확인한 정확한 대상과 내용으로 권한을 제한한다.
- 민감 원문을 권한 저장소와 감사 로그에 복제하지 않는다.
- 고위험·외부·읽기 민감 동작은 반복 승인 경계를 유지한다.

## 결과

- 같은 앱 실행처럼 scope가 동일한 R1 동작은 30일 동안 승인창 없이 실행된다.
- 기억 값이나 예약 내용이 달라지면 새 scope이므로 다시 승인을 요구한다.
- 만료·철회된 grant는 즉시 매칭 대상에서 제외된다.
- 지속 승인으로 자동 실행된 호출도 `approval_decisions.scope`에 grant ID를 남기고 실행 결과를 기존 감사 기록에 저장한다.
