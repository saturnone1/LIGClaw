# ADR 0011 — Desktop 소유 개인 기억

## 결정

개인 기억은 Desktop의 기존 SQLite 데이터베이스에 `memories` 테이블로 저장하고 Sidecar에는 저장소 접근권을 주지 않는다. 기억은 `kind + key`로 upsert하며 값, 출처, 민감도, 생성·수정 시각과 선택적 만료 시각을 보존한다.

모델은 `memory.remember.v1`, `memory.list.v1`, `memory.forget.v1` 계약만 사용할 수 있고 세 Tool 모두 매 호출 사용자 승인을 요구한다. 기억 값은 승인 화면과 모델 결과에만 포함하고 진단 및 실행 감사 요약에는 기록하지 않는다. API 키, 비밀번호, 인증 토큰을 의미하는 키와 알려진 자격 증명 형태의 값은 Desktop 정책에서 거부한다.

모델 입력에는 저장 출처를 받지 않는다. 정상 Tool 실행 경로에서 Desktop이 신뢰한 `conversationId`를 `conversation:<id>` 형식으로 주입하고, 로컬 관리 화면에서 직접 저장한 경우에만 `local-management`를 사용한다.

사용자는 모델과 무관하게 기억 관리 화면에서 활성·만료된 모든 기억을 검색·추가·수정하고 명시적 확인 후 삭제하거나 민감 원문 경고 후 JSON으로 내보낼 수 있다.

OpenAI 호환 모델이 개인 선호 질문에서 `memory.list.v1`을 누락하거나 잘못된 Tool을 선택할 수 있으므로, Sidecar는 제한된 명시적 선호 조회 문장(에디터·브라우저·터미널·개발 언어·테마)을 모델 호출 전에 `memory.list.v1`로 라우팅한다. 시스템 RAM 질문은 제외하며 Desktop의 R1 승인·감사 경로를 그대로 거친다. 조회 결과는 ID·출처를 노출하지 않고 키와 값만 제한적으로 렌더링한다.

같은 범주의 명시적 선호 저장 문장도 `memory.remember.v1`로 직접 라우팅한다. 이는 기존 값과 같을 때 일부 모델이 줄바꿈만 반환하거나 성공 결과의 내부 memory ID를 노출하는 동작을 피한다. Desktop 결과의 `created` 여부만 사용해 저장·업데이트 문구를 만들며 ID는 사용자 답변에 포함하지 않는다.

## 이유

- Sidecar 교체나 재시작이 개인 데이터를 소유하지 않게 한다.
- 모델의 암묵적 프로필 생성을 차단하고 사용자가 저장·조회·삭제를 통제한다.
- 만료와 출처를 데이터 모델에 포함해 후속 별칭 해석과 내보내기에서 추적 가능성을 유지한다.
- 인증정보는 Windows Credential Manager 경계에 남기고 일반 기억 DB로 복제하지 않는다.

## 결과

- SQLite schema version은 4가 된다.
- 같은 종류와 키를 다시 기억하면 기존 ID를 유지한 채 갱신한다.
- 만료된 기억은 모델 조회와 별칭·선호 해석에서 제외되지만 관리 화면에는 `만료됨`으로 표시해 사용자가 수정·삭제·내보낼 수 있다.
- DB 백업에는 개인 기억 값이 포함되므로 로컬 민감 데이터로 취급한다.
- `$alias:<키>`와 `$preference:<키>`는 제한된 Windows Tool 대상 인자에서만 Desktop이 해석한다. 승인 preview에서 확정한 값을 실행까지 고정하고 Sidecar에는 값을 반환하지 않는다.
- 관리 목록은 저장소 offset paging을 끝까지 순회하므로 500개를 넘어도 검색·내보내기에서 누락하지 않는다.
