# LIGClaw UI 상태·사용자 여정 계약

> 상태: UX-0 기준선  
> 기준일: 2026-07-26

이 문서는 UI 개편 중 기능 상태가 누락되거나 무반응 경로가 생기지 않도록 화면이 반드시 표현해야 하는 상태와 복구 행동을 고정한다.

## 1. 전역 셸 상태

| 상태 | 사용자에게 보이는 표현 | 가능한 행동 | 복구/종료 조건 |
|---|---|---|---|
| 시작 중 | 짧은 준비 문구와 진행 표시 | 로컬 관리 화면 탐색 | 저장소와 Sidecar 초기화 완료 |
| 사용 가능 | 연결됨 상태, 활성 입력창 | 요청 전송, 관리 기능 사용 | 요청 시작 또는 연결 변화 |
| 모델 미설정 | 설정 필요 banner | `모델 연결 설정` | 연결 정보 저장과 검사 성공 |
| 연결 끊김 | 원인 범주의 설명과 `다시 연결` | 로컬 활동·기억·예약·설정 | 재연결 성공 |
| 저장소 제한 | 로컬 데이터 기능 제한 banner | 대화 연결·설정·재시도 | 저장소 초기화 성공 또는 앱 재시작 |
| 종료 중 | 중복 입력 차단 | 없음 | 프로세스 종료 |

전역 상태는 색만으로 구분하지 않고 상태명과 다음 행동을 함께 표시한다.

## 2. 대화 상태

| 상태 | 타임라인 | 입력 영역 | 필수 피드백 |
|---|---|---|---|
| 빈 대화 | 환영 문구와 안전한 예시 요청 | 활성 | 예시는 선택만 하며 자동 실행하지 않음 |
| 입력 중 | 기존 대화 유지 | 자동 높이, 보내기 활성 | `Ctrl+Enter` 도움말 |
| 전송 중 | 사용자 요청 즉시 추가 | 중복 전송 차단, 중단 표시 | polite live region으로 진행 안내 |
| 응답 streaming | 응답 항목에 점진 표시 | 중단 가능 | 사용자가 위를 읽는 중이면 강제 하단 이동 금지 |
| 승인 대기 | 해당 도구 카드에 승인 대기 | 새 요청 차단 | 승인 창과 대상·영향 연결 |
| 도구 실행 중 | 사용자용 동작과 진행 상태 | 중단 가능 여부 표시 | 장시간 작업 상태 갱신 |
| 완료 | 답변과 도구 결과 확정 | 다시 활성 | 후속 요청 가능 |
| 실패 | 실패 지점과 안전한 요약 | 다시 활성 | 가능한 복구 행동 제공 |
| 취소 | 취소된 범위 명시 | 다시 활성 | 부분 실행 결과가 있으면 함께 표시 |

## 3. 승인 상태

승인 화면은 modal로 유지하며 다음 정보를 이 순서로 제공한다.

1. 사용자가 이해할 수 있는 동작 이름
2. 실제 대상과 영향 범위
3. 위험 수준과 그 의미
4. 되돌릴 수 있는지 여부
5. 허용 범위와 만료
6. 거부와 허용 행동

기본 포커스가 위험 동작의 승인에 놓이지 않도록 한다. 창 생성 또는 데이터 표시 실패 시 호출 화면에 오류와 재시도 가능 여부를 반드시 표시한다.

## 4. 관리 페이지 상태

활동·기억·예약 페이지는 초기 로딩, 데이터 있음, 빈 데이터, 검색 결과 없음, 저장 중, 성공, 실패, 삭제·되돌리기 상태를 공통으로 지원한다. 실패는 원인 범주와 재시도 또는 안전한 대안을 보여주며, 변경 뒤에는 대상 행으로 포커스를 복원한다.

## 5. 설정 연결 여정

`입력 검증 → 연결 테스트 → 안전한 키 저장 → 적용 결과` 순서로 진행한다.

- URL, 모델, 키의 입력 오류는 해당 필드 가까이에 표시한다.
- 연결 테스트 중 버튼과 상태 문구가 함께 busy 상태를 나타낸다.
- 공급자 원문, API 키, 응답 본문은 진단과 UI에 노출하지 않는다.
- 실패 시 네트워크, 인증, 모델, 형식, 시간 초과 중 안전한 범주와 다음 행동을 제공한다.
- 저장된 키 유지와 새 키 교체를 구분해 표시한다.

## 6. 핵심 키보드 흐름

1. 앱 열기 → 요청 입력 → `Ctrl+Enter` 전송 → 중단 → 입력 복귀
2. 탐색 → 활동 → 필터/목록 → 되돌리기 확인 → 원래 행으로 포커스 복귀
3. 탐색 → 기억 → 검색 → 추가/수정 → 저장 → 변경된 항목으로 포커스 복귀
4. 탐색 → 예약 → 확인 필요 항목 → 실행/건너뛰기 → 결과 확인
5. 탐색 → 설정 → 연결 정보 → 테스트 → 저장 → 대화로 복귀

Tab 순서는 시각 순서와 일치해야 하며 modal을 닫으면 호출한 컨트롤로 포커스가 돌아간다.

## 7. 반응형 기준

| 조건 | 셸 | 대화/관리 본문 |
|---|---|---|
| 폭 1000px 이상 | 전체 탐색과 최근 대화 | 필요 시 보조 상태 열 허용 |
| 폭 760~999px | 축소 탐색 | 단일 열, 보조 정보 접기 |
| 150~200% 배율 | 축소 탐색 우선 | 주요 버튼과 입력이 viewport 안에 유지 |
| 높이 500px | 고정 입력 최소 높이 | 본문만 scroll, 주요 행동은 접근 가능 |

## 8. 자동 검증 계약

- 모든 사용자 입력 컨트롤과 icon-only 버튼에 접근성 이름이 있다.
- 상태 변경 영역은 적절한 live setting을 사용한다.
- 읽기 전용 view data 바인딩은 명시적으로 OneWay다.
- 화면에 직접 선언하는 색상은 공식 심벌 자산처럼 문서화된 예외만 허용한다.
- 주요 창은 최소 크기에서 열리고 page title, primary action, 오류 복구 동작을 UI Automation으로 찾을 수 있다.
