# LIGClaw UI/UX 전면 개선 계획

> 상태: UX-0~UX-5 완료
> 기준일: 2026-07-26
> 범위: WPF 데스크톱 셸과 모든 사용자 대면 관리·승인 화면

## 1. 목표

LIGClaw를 기능별 팝업의 집합이 아니라, 사용자가 현재 상태와 다음 행동을 즉시 이해할 수 있는 하나의 Windows 비서 경험으로 개편한다.

성공 기준은 다음과 같다.

- 앱을 처음 연 사용자가 별도 설명 없이 모델 연결, 요청 입력, 실행 승인, 결과 확인까지 진행할 수 있다.
- 대화, 실행 상태, 승인, 오류, 복구 행동이 한 흐름 안에서 이어진다.
- 실행 활동·기억·예약·설정은 일관된 탐색과 목록 패턴을 사용한다.
- 760×500 최소 창과 지원되는 반응형 레이아웃에서 핵심 동작이 잘리지 않는다.
- 키보드만으로 모든 주요 기능을 사용할 수 있고 포커스, 상태, 오류가 색상에만 의존하지 않는다.
- UI 예외가 무반응으로 끝나지 않으며 사용자가 이해할 수 있는 메시지와 복구 동작을 제공한다.

## 2. 현재 UX 문제

코드와 현재 화면 구조를 기준으로 다음 문제를 우선 해결한다.

1. 메인 화면의 입력, 답변, 런타임 상태, 진단 패널이 동시에 강조되어 핵심 대화 흐름이 좁다.
2. 설정·실행 활동·기억·예약이 모두 modal 창이라 탐색 맥락이 끊기고 여러 화면의 동작 패턴이 다르다.
3. 대화 응답은 문서 영역에 표시되지만 사용자 요청과 도구 진행 과정은 하나의 타임라인으로 보이지 않는다.
4. 연결 실패, 저장소 실패, 도구 실패의 표현과 복구 버튼이 화면마다 일관되지 않다.
5. 리스트 화면은 검색·필터·빈 상태·행 동작·삭제 확인의 공용 패턴이 없다.
6. 작은 창과 고배율에서 고정 폭 사이드바와 다열 콘텐츠가 대화 가용 공간을 크게 줄인다.
7. 스타일 토큰은 있으나 타이포그래피, 간격, 아이콘, 상태 배지, focus visual, skeleton/loading 규칙이 충분히 체계화되지 않았다.

## 3. 제품 구조

### 3.1 통합 앱 셸

메인 창을 다음 다섯 목적지의 통합 셸로 바꾼다.

- 대화: 요청과 응답, 도구 진행, 취소 및 후속 행동
- 활동: 실행 이력, 승인 결과, 실패 상세, 되돌리기
- 예약: 예정·확인 필요·완료 항목 관리
- 기억: 검색, 추가, 수정, 삭제, 내보내기
- 설정: 모델 연결, 빠른 호출, 시작 동작, 개인정보 및 진단

넓은 창에서는 축소 가능한 왼쪽 탐색을 사용하고, 좁은 창에서는 아이콘 중심 rail 또는 상단 전환으로 바꾼다. 관리 화면을 기본적으로 앱 내부 페이지로 전환하되, 보안 승인은 소유자가 명확한 modal로 유지한다.

### 3.2 대화 중심 화면

- 답변을 독립 카드가 아닌 사용자 요청과 응답이 이어지는 대화 타임라인으로 표시한다.
- 입력창은 화면 하단에 고정하고 자동 높이, 명확한 보내기·중단 상태, 키보드 도움말을 제공한다.
- 도구 실행은 타임라인 안의 진행 카드로 표시하고 `확인 중 → 승인 대기 → 실행 중 → 완료/실패` 상태를 보여준다.
- 시스템 상태와 문제 해결 정보는 평상시 최소화하고 이상이 있을 때만 문맥에 맞는 banner를 표시한다.
- 빈 화면에는 실제 기능과 연결된 예시 요청을 제공하되 자동 실행하지 않는다.

### 3.3 일관된 관리 화면

활동·예약·기억은 공용 page header, 검색/필터 bar, list row, empty state, status badge, confirmation 패턴을 공유한다. 파괴적 동작은 행의 기본 버튼으로 강조하지 않고 명시적 확인과 영향을 표시한다.

## 4. 디자인 시스템 v2

기존 공식 BrandBlue와 BrandGray는 유지하면서 의미 토큰을 확장한다.

- 색상: canvas/surface/elevated, accent, success/warning/danger/info 및 각 subtle surface
- 타이포그래피: display, page title, section title, body, caption, mono의 크기·행간
- 간격: 4px 기반 spacing scale과 페이지·카드·행 밀도
- 형태: radius, border, elevation, divider, overlay
- 컨트롤: navigation item, command button, icon button, status badge, banner, list row, empty state, inline error, loading indicator
- 상태: normal, hover, pressed, selected, disabled, focus-visible, busy

색상과 숫자는 화면 XAML에 직접 넣지 않고 공용 리소스를 사용한다. 아이콘은 한 가지 선 굵기와 동일한 optical size를 사용하고, 텍스트 label 또는 접근성 이름을 항상 제공한다.

## 5. 실행 단계

현재 진행 기록(2026-07-26): UX-0부터 UX-5까지 완료했다. 설정·활동·기억·예약을 단일 MainWindow 내부 페이지로 전환하고 760px compact layout, 대화 타임라인, 하단 composer, 연결 복구 banner, 관리 화면 공용 패턴, 안전한 Markdown, UI 예외 안전망과 UI Automation smoke를 구현했다. 후속 안정화에서 명시적 `새 대화` 경계와 최근 대화별 다중 턴 복원, 같은 대화의 후속 요청 문맥 유지, 실행 실패 시 기존 타임라인 보존을 추가했다. 사용자 결정에 따라 물리 다중 모니터와 별도 배율 장비 검증은 필수 완료 조건에서 제외한다. 세부 증거는 `docs/UI_UX_ACCEPTANCE.md`에 기록한다.

### UX-0 — 기준선과 화면 계약

- 현재 주요 화면과 상태 목록 작성: 빈 상태, 로딩, 연결 끊김, 실행 중, 승인, 실패, 완료
- 핵심 사용자 여정과 키보드 tab order 정의
- 공용 화면 구성 요소와 ViewModel 경계 확정
- 렌더링 회귀 검사에 사용할 대표 창 크기와 배율 정의

완료 조건: 모든 사용자 여정에 시작 상태, 성공 상태, 실패·복구 상태가 문서화된다.

### UX-1 — 디자인 시스템 v2

- semantic token과 typography/spacing scale 정리
- 공용 button, input, navigation, card, badge, banner, dialog 스타일 구현
- focus visual, disabled, validation, busy 상태 통일
- 기존 화면의 인라인 색상과 중복 스타일 제거

완료 조건: 새 화면이 개별 색상·여백을 선언하지 않고 공용 리소스로 구성되며 XAML 리소스 검사가 통과한다.

### UX-2 — 통합 셸과 반응형 탐색

- MainWindow를 page host와 축소 가능한 navigation으로 개편
- 설정·활동·기억·예약을 앱 내부 페이지로 이동
- 좁은 폭과 고배율에서 탐색과 본문이 겹치지 않는 adaptive layout 구현
- 페이지 전환, 뒤로 가기, 마지막 위치 복원, 명확한 선택 상태 제공

완료 조건: 주요 관리 기능을 modal을 연속해서 열지 않고 한 창에서 이동할 수 있다.

### UX-3 — 대화와 실행 경험

- 사용자/도우미/도구 이벤트를 하나의 대화 타임라인으로 표현
- 고정 composer, 자동 높이, 전송/취소/busy 상태 개선
- 연결·실행·오류 상태를 문맥 banner와 inline recovery action으로 제공
- streaming 중 레이아웃 흔들림과 불필요한 자동 스크롤 방지
- 표, 코드, 목록, 링크의 가독성과 복사 동작 개선

완료 조건: 요청부터 도구 결과까지 시간 순서와 현재 상태가 한 화면에서 이해된다.

### UX-4 — 관리·승인·안전 경험

- 활동·예약·기억 목록의 검색, 필터, 정렬, 빈 상태, 행 동작 통일
- 승인 창에 대상, 영향, 위험 수준, 취소 가능 여부를 계층적으로 표시
- 되돌리기와 삭제는 결과 toast/banner 및 실패 복구를 제공
- 설정의 모델 연결을 입력 검증 → 테스트 → 저장의 단계형 흐름으로 개선

완료 조건: 모든 쓰기 동작에 실행 전 영향과 실행 후 결과가 보이며 무반응 경로가 없다.

### UX-5 — 접근성·품질·실기 acceptance

- keyboard-only, screen reader name/live region, focus restore 검사
- 760×500부터 일반 데스크톱 크기까지 반응형 레이아웃 검사
- light/high-contrast, 긴 한국어/영문, 빈 데이터/대량 데이터 검사
- UI 이벤트 예외와 modal 생성 실패 회귀 테스트
- UI Automation smoke로 탐색, 요청 입력, 활동 열기, 설정 연결 흐름 검증

완료 조건: 현재 지원 범위의 자동 검증과 수동 acceptance 표가 모두 통과하고 `./scripts/verify.ps1`이 성공한다. 물리 다중 모니터와 별도 배율 장비 검증은 필수 조건이 아니다.

## 6. 구현 원칙

- Domain과 Application에는 WPF 의존성을 추가하지 않는다.
- UI 상태와 화면 전환 로직은 가능한 한 ViewModel 또는 testable presenter로 분리한다.
- 보안 승인, Windows 효과, 비밀 저장소의 Desktop 소유권은 변경하지 않는다.
- 화면 개편 중 protocol과 Tool 계약은 필요한 경우가 아니면 변경하지 않는다.
- 큰 개편도 각 단계에서 실행 가능한 작은 수직 슬라이스로 병합하고 기존 기능을 잃지 않는다.
- 사용자가 만든 현재 작업 트리 변경을 보존하며 UI 변경과 무관한 코드는 재작성하지 않는다.

## 7. 우선순위와 제외 범위

우선순위는 `대화 핵심 흐름 → 오류·승인 피드백 → 통합 탐색 → 관리 화면 → 시각 완성도` 순이다. 이번 목표에서 WinUI 3 마이그레이션, 음성, OCR/VLM, 브라우저 자동화, 새 Windows Tool 추가는 제외한다. 이들은 UI 기반이 안정된 후 별도 제품 기능으로 진행한다.

## 8. 최종 완료 정의

- UX-0부터 UX-5까지 완료되고 각 단계의 acceptance가 기록되어 있다.
- 주요 사용자 여정에 UI Automation 또는 결정적 presenter/view-model 테스트가 있다.
- 기존 대화·도구·기억·예약·설정 기능이 회귀 없이 동작한다.
- 전체 검증이 경고와 오류 없이 통과한다. 기존에 기록된 미사용 Dify 하위 의존성의 low advisory는 별도 의존성 항목으로 추적한다.
- `docs/DESIGN_SYSTEM.md`가 구현된 v2 기준과 일치하고 실제 화면 검토 결과가 문서화된다.
